# General Development Guide

These are defaults across languages and projects. Follow the language and project conventions where syntax or framework choices differ.

## Writing Style
- Do not use em dashes (—). Use a plain hyphen (-) instead.
- Applies to all written output: PR comments, code review feedback, documentation, commit messages, and code comments.

## Architecture & Principles
- KISS and DRY above all else. Start simple and evolve only when needed.
- Every abstraction must justify its existence. If unsure, choose the simplest solution.
- Prefer composition over inheritance.
- Avoid premature abstractions, unnecessary interfaces, wrapper types without clear value, and layers introduced just in case.
- Do not split files only for organization.
- Isolate third-party APIs behind facades at boundaries where it reduces coupling; avoid wrappers without clear value.

## Naming & Code Style
- Use clear, descriptive names, as short as possible without abbreviations.
- Follow the language and project naming conventions.
- Code must be self-explanatory. Prefer clearer names and structure over explanatory comments.
- Comments must earn their place by explaining something the code cannot convey.
- Prefer typed keys and configuration over raw strings where the language supports them.

## Error Handling
- Propagate failures explicitly using the language conventions; let the caller decide how to handle them.
- Handle and log useful failures rather than swallowing them silently. Preserve the error object and diagnostic context in logs.
- Show errors to the user only when the entire operation fails; log partial failures.
- Use a fallback only when it is semantically correct. If failure is useful for debugging, log it even when continuing.

## AI Assistant Rules
- Never add AI signatures, attribution comments, or "generated by" notes in code.
- Never commit or stage files without explicit user request.
- Never run destructive git operations (reset --hard, force push, branch -D, clean, etc.) without explicit user approval.
